# 現場交接：辦公室 ↔ 真機

## 為什麼有這份

這台設備的開發分兩個地方做，兩邊能做的事不一樣：

- **辦公室**：只能模擬。跑建置、跑測試、用 mock 或錄下來的資料；跑不到真硬體。
- **真機現場**：接得到硬體，能直接測。後端機、EtherCAT 環、軸、磁浮、氣缸、起子在這裡。

工作在兩地之間搬，靠**一份帶日期的交接檔**接力：下一個在另一邊的人（或 agent）先讀那一份，就知道現在在哪、下一步做什麼、哪些只有這裡做得到。**一次移動、一個方向、一份檔。**

## 先選方向

| 你正要… | 寫哪一份 | 檔名 |
|---|---|---|
| 離開辦公室、要去（或要去人）**真機** | **辦公室 → 真機** | `.scratch/HANDOFF-<YYYY-MM-DD>-field.md` |
| 從真機收工、要回**辦公室** | **真機 → 辦公室** | `.scratch/HANDOFF-<YYYY-MM-DD>-field-to-office.md` |
| 要給現場一台**沒有 repo** 的電腦一份自帶資訊的提示詞 | 附在辦公室 → 真機那份旁 | `.scratch/handoff-<YYYY-MM-DD>-field-agent-prompt.md`；MetalAutoUQDwpf 例外：`.scratch/handoff-field-agent-prompt-<N>.md`，形狀見 `field-office-checklist` |

不確定方向就問使用者。**舊交接檔不要刪、不要改** —— 新版在開頭寫一句「前一份是 …，本檔只補今天多的」，讓它自然退場。

## 辦公室 → 真機 要寫什麼

按這個骨架寫；每一節沒有事實就明講「還沒有／量不到」，不要留空當沒這回事。

1. **標題 + 一句定位**：`交接：辦公室 → 真機（下次開真機電腦先讀這一份）`，日期，前一份是誰。
2. **為什麼要有這一份**：git **帶不過去**的東西。exe 旁那份 `uqd.json` 在 `.gitignore` 底下、不會跟 pull 下來；真機設定要在真機上補。把這種「不是壞掉、是要手動補」的事講清楚，否則現場會以為程式壞了。
3. **pull 下來就有的**：辦公室這趟合進 master 了什麼，哪些是**真機上看得到的行為改變**（表格：改變 → 真機上要注意什麼）。沒上過真機的，明講「還沒驗」。
4. **真機上照順序做**：編號步驟，每步給**可直接貼的指令**（pull → 使用者關 HMI → 補設定檔腳本 → 建置 → 測試 → 開 HMI → commit／push），並寫「要看到什麼才算成功」。
5. **症狀怎麼查**：手上這個壞掉/沒動的現象，先看什麼、再看什麼（有序的唯讀探針），以及**紅旗**（出現就叫人停下來、抄原文、不要自己修）。
6. **收工還沒做**：只有真機做得到的，列成 `- [ ]` 清單。

## 真機 → 辦公室 要寫什麼

1. **標題 + 一句定位**：`交接：真機 → 辦公室（<日期>）`。
2. **真機現況**：部署中的 backend 版本（`build_id` / commit）、現場 WPF exe 是哪個 commit 建的、**動過的真機設定**（設定檔改了什麼、備份在哪）。
3. **驗收做到哪**：哪幾張票的哪幾步過、哪幾步沒做。**沒做完就寫沒做完**，不要含糊。
4. **已開票的**：表格 `issue | 哪一邊（WPF／backend） | 一句話`。
5. **看到、還沒開票的**：現場看到但還沒判斷的，留給辦公室決定要不要開票。
6. **今天改的程式**：表格 `commit | 內容 | 真機驗了沒`。
7. **證據在哪**：兩台機器的 log 路徑都寫（現場 WPF 側、後端機側、vault），並寫明哪一份是關鍵證據。

## 現場 agent 提示詞（要給「沒有 repo 的現場電腦」時才寫）

一份**自帶全部字串與量法**的貼上即用提示詞，讓那台沒有 repo 也夠用。必須含：

- **身分**：你是這台機器的現場支援 agent；工作是把量測做完、把原值與判讀**一字不漏帶回** —— 不是改程式、不是修機器。
- **環境**：哪一台、後端連哪、當天該看哪份 log。
- **優先序（P0→P3）**：先做哪幾張、為什麼（哪張卡住其他驗收）。
- **回報骨架**：一段現成的 markdown，讓它填完就成報告（版本、每一項要抄的原文／數字、結論、量不到的）。

MetalAutoUQDwpf 的專用版由 `field-office-checklist` 產（A／B／C 三層、每格寫「怎麼做、要看到什麼、票」、檔名 `handoff-field-agent-prompt-<N>.md`）；這節只定通用必要元素。

## 鐵律（兩個方向共用，比任務更嚴）

1. **先抄再改**：任何量測都在改設定、重啟之前抄完原值。
2. **量不到就照實寫「量不到＋為什麼」**，不猜、不補、不推論。
3. **現場 agent 不下會動的命令**：軸、磁浮、氣缸、起子、DIO 輸出點測，一律由使用者本人按；agent 只讀遙測、看畫面、截圖、記錄。
4. **sudo 與工程師 PIN 由使用者本人打。**
5. **不自己重啟 backend**（會扯掉 EtherCAT 環、L6N 要按故障復歸）；要重啟先問使用者。
6. **訊息逐字抄原文**，不改寫成自己的話。
7. **push、合併、部署前先問**使用者。
8. 回報繁體中文、結論先行、數字照實、檔案用完整相對路徑。

這些是**交接檔的內容**，也是現場提示詞的核心；兩邊都要有。

## 流程

1. **選方向、定檔名**。Done when：方向與檔名都定了。
2. **盤點現況**：`git log`／`git status`、兩邊部署版本、`ready-for-human` 的票清單。Done when：你手上有版本號與那張清單。 MetalAutoUQDwpf 的票清單與 A／B／C 分層用 `field-office-checklist` 產。
3. **只讀取證**：照對應方向的骨架，一節一節蒐集事實；取不到的當場記成「量不到＋為什麼」。Done when：每一節都有一個事實或一句明講的「還沒有」。
4. **寫交接檔**到 `.scratch/`，照骨架。**引用不複製**：票、spec、ADR、commit 用路徑／編號指過去，不要把內容抄進來。Done when：每個 bullet 指向一個路徑或一句事實。
5. **（只有辦公室 → 真機）產生現場提示詞**，若對象是沒有 repo 的電腦。Done when：它自帶全部字串與量法，貼上就能用。
6. **交叉連結**：把新交接檔跟它提到的票互相指到；照 repo 規矩（檔案 CRLF、commit 一行短句、push 前先問）。Done when：連結雙向、且沒動到不該動的東西。
7. **回報**：跟使用者講「入口是哪一份檔、這次學到什麼、下一次誰要做什麼」。Done when：他從你的訊息就能找到那份檔。

## Rationalizations

| 藉口 | 事實 |
|---|---|
| 「反正另一邊 pull 下來就同步了。」 | exe 旁的 `uqd.json`、真機設定、log 都在 git 之外。不寫，現場就是從錯的狀態開始。 |
| 「票的內容我貼一份進來比較好看。」 | 貼進來就會跟票本身分岔。用路徑引用，票是唯一真相。 |
| 「順手把程式也改了。」 | 現場 agent 的任務是量測。改程式要開票、回辦公室做（或開 worktree、先問）。 |

## 紅旗

- 交接檔沒有日期，或沒說它取代哪一份。
- 只寫「做完了」，沒寫「哪些沒做／沒驗」。
- 數字沒有出處（沒有 log 檔名、沒有 commit、沒有量法）。
- 現場那一份貼給沒有 repo 的電腦，卻只寫相對路徑、沒帶齊字串。
- 動了會動的命令、打了 sudo／PIN、或重啟了 backend 卻沒問使用者。
