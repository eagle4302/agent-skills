# 流暢度檢查清單

> 用法：每次驗證先挑要驗的維度，逐項打勾。沒過的項目要留下證據（畫面、時間、引述、量測值）。
> 不確定的標「待驗」，不要用猜的填「通過」。

## 1. Flow（動線）

### 入口與意圖

- [ ] 一進畫面就知道這頁在做什麼、下一步該去哪
- [ ] 主要動作在首屏可見，不需要捲動或尋找
- [ ] 次要動作不搶主要動作的視覺重量
- [ ] 從其他畫面進來時，有足夠的上下文（標題、麵包屑、選取的產線／設備）

### 路徑

- [ ] 關鍵任務步數 ≤ 規劃值 + 1
- [ ] 每個畫面都有明確的返回、取消或離開路徑
- [ ] 沒有死路：任何狀態下都能繼續、返回或重設
- [ ] 破壞性動作有二次確認，且預設焦點在「取消」
- [ ] 中斷後可恢復：切換畫面、重新整理、重進 app 後狀態正確
- [ ] 多步驟流程顯示進度與目前位置
- [ ] 重複性任務有批次或快捷路徑

### 資訊氣味

- [ ] 按鈕與連結文字說出目的地或結果，不是「確定」「執行」
- [ ] 清單列的可點區域明確，不是只有文字可點
- [ ] 篩選、排序、搜尋後有「目前條件」提示與一鍵重設
- [ ] 空狀態提供下一步，而不是只說「沒有資料」
- [ ] 分頁與捲動的行為一致，不會兩者混用造成迷失

## 2. Clarity（認知）

### 狀態

- [ ] 八種狀態可一眼辨識：正常、載入中、空資料、錯誤、警報、離線、無權限、停用
- [ ] 資料新鮮度可見：最後更新時間、延遲、取樣頻率
- [ ] 操作後有回饋：loading、成功、失敗、部分成功
- [ ] 警報與一般通知在視覺上可區分，且不會互相淹沒

### 控制項

- [ ] 可點元素看起來可點；不可點的不像可點
- [ ] 停用狀態說明原因，不只是變灰
- [ ] 錯誤訊息說「發生什麼、影響什麼、怎麼修」，不是只給代碼
- [ ] 危險動作與一般動作在顏色、位置、文案上可區分
- [ ] 同一種控制項在不同畫面行為一致

### 文案

- [ ] 使用使用者領域詞彙，不用內部代號或縮寫
- [ ] 單位、格式、時區全畫面一致
- [ ] 缺值顯示 `—` 或「尚未更新」，不是空白或 0
- [ ] 數字千分位、小數位數符合規範

## 3. Feel（手感）

### 回饋

- [ ] 點擊或觸控到視覺回饋 ≤ 100ms（目標 ≤ 50ms）
- [ ] hover、focus、pressed、disabled 四態都有定義
- [ ] 焦點外框可見，且不被容器或 `overflow: hidden` 裁掉
- [ ] 送出後按鈕進入 loading，並防止重複送出
- [ ] 長動作有進度或可取消，不是無反應的等待

### 動效

- [ ] 動畫時長符合 token（120／200／320ms）
- [ ] 動畫不阻擋操作，且可被中斷
- [ ] 尊重系統「減少動畫」設定
- [ ] 資料刷新不做大幅位移或閃爍

### 輸入

- [ ] Tab 順序符合視覺順序（由上到下、由左到右）
- [ ] 所有動作可用鍵盤完成，且焦點不遺失
- [ ] 觸控目標 ≥ 44px；現場或戴手套建議 48px
- [ ] 滾動、縮放、拖曳不卡頓
- [ ] 中文輸入法選字、游標與組字視窗不破版

### 資料更新

- [ ] 每秒更新時版面不跳動、不閃爍
- [ ] 數字變更不造成寬度跳動（等寬字與固定欄寬）
- [ ] 更新中斷（離線、API 失敗）有明確提示與重連狀態
- [ ] 大量更新時不凍結 UI（分批或虛擬化）

## 4. Robustness（韌性）

- [ ] 0 筆資料顯示空狀態，不是空白畫面
- [ ] 最大筆數（例 1000 筆）可捲動、可分頁、效能可接受
- [ ] 超長文字會截斷或換行，不與相鄰元素重疊
- [ ] 極大、極小、負數、`NaN`、缺值都正確顯示
- [ ] 快速連點不產生重複動作或重複請求
- [ ] 錯誤可重試，重試有回饋且不累積錯誤狀態
- [ ] 離線 → 恢復連線後資料正確，不殘留舊狀態
- [ ] 30 分鐘 soak：記憶體與幀時間穩定
- [ ] DPI 125%／150%、視窗縮放、多螢幕下版面正常
- [ ] 系統字型缺失或替換時不破版

## 5. Accessibility（可及性）

- [ ] 正文對比 ≥ 4.5:1；大字 ≥ 3:1
- [ ] 狀態不只靠顏色（搭配文字、圖示或形狀）
- [ ] 所有互動元素有可讀名稱（`Accessible.name`／`aria-label`／`AutomationProperties.Name`）
- [ ] 表單錯誤與對應欄位關聯
- [ ] 螢幕閱讀器能讀出關鍵狀態與數值
- [ ] 高對比與減少動畫模式可用
- [ ] 鍵盤焦點順序與視覺順序一致

## 6. 啟發式檢查（Nielsen 10，改寫）

1. 系統狀態可見：現在發生什麼、還要多久。
2. 貼近真實世界：用使用者的語言與順序。
3. 使用者可控制：取消、復原、離開。
4. 一致與標準：同一件事在不同畫面長一樣。
5. 錯誤預防：限制輸入、預設安全選項、確認危險動作。
6. 辨識優於回憶：選項看得到，不用記。
7. 彈性與效率：快捷鍵、批次、範本。
8. 簡潔與聚焦：一屏一個主要任務。
9. 錯誤恢復：說清楚、給出路、保留資料。
10. 說明與協助：必要時在現場提供，不藏在文件裡。

## 7. 問題分級

| 等級 | 定義 | 例子 |
|---|---|---|
| Blocker | 任務無法完成、資料錯誤或遺失、崩潰、安全相關狀態不清 | 確認警報後仍顯示未確認；離線時按鈕無反應 |
| Major | 任務可完成，但出現迷路、死路、繞路，或使用者明顯感受到的手感問題 | 需要關掉抽屜才能看到被遮住的按鈕 |
| Minor | 拖慢但未改變結果 | 多一次點擊、錯誤訊息不夠具體 |
| Cosmetic | 只影響觀感，不影響任務或理解 | 對齊差 1px、動畫曲線不順 |

## 8. 使用規則

- 同一個問題只記一次，合併到一個 issue id。
- 每個未通過項目都要有證據；沒有證據的項目標「待驗」。
- 清單是輔助，不是覆蓋率證明：任務走查與量測才是主要證據。
- 若專案已有自己的設計系統或工安規範，以專案規範為準並註明。
